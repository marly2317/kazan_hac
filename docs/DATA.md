# Данные: справочник КТРУ

## Что дали организаторы

| Путь | Содержимое |
| --- | --- |
| `КТРУ/КТРУ/*.zip` | 183 архива, внутри каждого `nsiKTRUNew_all_actual_*.xml` |
| `Примеры выгрузок/*.xlsx` | Инструменты, Мебель, Одежда — реальные СТЕ |

Файлы `*_not-actual_*` организаторы просят игнорировать; парсер их и не читает.

Размер полного справочника, посчитанный по архивам: **81 465 позиций, из них 60 087
активных**, 234 363 характеристики, 503 группы ОКПД2.

## Структура XML

Элементы в пространстве имён `oos:`; корень — `<export><nsiKTRUs><oos:position>`.

```
oos:position/oos:data
├── code              25.73.30.141-00000001      ← целевой код
├── name              Молоток
├── status            ACTIVE | TERMINATED        ← берём только ACTIVE
├── OKPD2/code,name   25.73.30.141
└── characteristics/characteristic
    ├── name          Длина рукоятки
    ├── type          1 качественная | 2 количественная
    ├── actual        false → характеристика снята
    ├── isRequired    обязательная ли
    └── values/value
        ├── qualityDescription          «Пластик»        (качественная)
        ├── valueSet/concreteValue      200              (точное значение)
        ├── rangeSet/valueRange         min/max + minMathNotation/maxMathNotation
        └── OKEI/code,name              003 / Миллиметр  (единица измерения)
```

**`greater`/`less` исключают границу, `greaterOrEqual`/`lessOrEqual` включают.** Спутать их —
значит принять значение, которое КТРУ отвергает, то есть ровно та ошибка, которую оценивают.
Реализовано в `PermittedValue.contains`, показано в `describe()` как `>` против `≥`.

Парсер: [`apps/ktru/infrastructure/xml_parser.py`](../backend/apps/ktru/infrastructure/xml_parser.py).

## Импорт

```bash
docker compose exec backend python manage.py import_ktru /data/ktru \
    --okpd2 14 --okpd2 15 --okpd2 25.73 --okpd2 28.24 --okpd2 31
```

`--okpd2` можно повторять; без него импортируется всё. Повторный запуск идемпотентен
(`update_conflicts`): КТРУ поставляет одну и ту же позицию в нескольких архивах, и падение на
дубликате прерывало бы нормальный импорт.

### Почему не весь справочник

Полный импорт выглядит правильнее, но ухудшает качество: **32.50 (медицина, 25 984 позиции)**
и **21.20 (лекарства, 11 483)** — это 62% активного справочника и чистый шум для трёх
категорий хакатона. «Стол операционный» начинает конкурировать со «столом письменным», а
«Отвертка» в 32.50 — это хирургический инструмент.

Текущее покрытие — 1812 позиций, 9029 характеристик, 43 815 допустимых значений:

| Префикс | Позиций | Что это |
| --- | --- | --- |
| 14.x | 879 | одежда |
| 31.x | 355 | мебель |
| 15.x | 326 | обувь и кожа |
| 25.73 | 205 | ручной инструмент |
| 28.24 | 47 | электроинструмент |

### Чего в справочнике нет

Это нужно знать, прежде чем чинить «ошибку» подбора. Проверено по всем 183 архивам:

* **отвёрток нет вовсе** — ни одной позиции с «отвертк» в наименовании вне медицинской группы;
* **перфораторов нет** — есть только «Бур для перфоратора» (25.73);
* обобщённых «Костюм» и «Перчатки» нет — только уточнённые («Костюм спортивный», «Перчатки
  трикотажные для защиты от внешних воздействий»);
* весь ручной инструмент — это 56 наименований в 25.73 и 16 в 28.24.

Правильное поведение сервиса на таком запросе — `state=not_found` с близкими позициями, а не
ближайшая строка, выданная за ответ. Случаи закреплены тестами в `scripts/eval.py`.

### Если расширять покрытие

Добавьте префикс в `--okpd2` и **обязательно** перезапустите `scripts/eval.py`: новые группы
приносят конкурирующие наименования, и то, что раньше определялось однозначно, может стать
`ambiguous`. После импорта сбросьте кэши корректора — `container.reset_spelling_indexes()` или
просто перезапуск бэкенда.

## Единицы измерения

Две разные задачи, разнесённые по файлам:

* [`ktru/infrastructure/units.py`](../backend/apps/ktru/infrastructure/units.py) —
  `канонический вид`: `кг`, `KG`, `Кг.` → `Килограмм`. Это **не** правописание: `кг` не
  опечатка, а сокращение, и редакционное расстояние их никогда не свяжет. Таблица
  достраивается именами ОКЕИ из импортированного справочника, поэтому остаётся верной при его
  изменении.
* [`ktru/domain/conversion.py`](../backend/apps/ktru/domain/conversion.py) — **перевод** между
  соизмеримыми единицами: `500 Грамм` → `0.5 Килограмм`. Только точные определительные
  коэффициенты, никогда через границу размерности, неизвестная единица не переводится ни во
  что.

## Примеры выгрузок

В `*.xlsx` характеристики лежат одной строкой: `Вес 2.03000 кг | Высота упаковки 100 мм | …`.
Там встречаются настоящие ошибки — например, `Кострукция сварная` в «Мебель.xlsx», которая и
стала тестовым случаем корректора.

Организаторы прямо указывают: **превалирующим является справочник КТРУ**, его характеристики и
значения. Выгрузки — источник реалистичных формулировок и ошибок, а не второй справочник.
