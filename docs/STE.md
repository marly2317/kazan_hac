# Подбор кода КТРУ и автозаполнение характеристик СТЕ

Модуль `backend/apps/ste` реализует архитектуру
[`materials/ARCHITECTURE_KTRU_ML.md`](../materials/ARCHITECTURE_KTRU_ML.md) (ссылки вида §4.3
ведут в неё). Схема в нотации BPMN: [`diagrams/ste.bpmn`](diagrams/ste.bpmn),
картинка — [`diagrams/ste-bpmn.svg`](diagrams/ste-bpmn.svg).

## Коротко

Поставщик пишет товар своими словами — «Болгарка Makita 125 мм 840 Вт от сети». Сервис:

1. исправляет опечатки и раскладку по словарю КТРУ;
2. находит **семейство КТРУ** (тип товара): поиск BM25 + эмбеддинги, затем LLM-1 выбирает из
   кандидатов — или поиск однозначен, и LLM-1 не нужна;
3. LLM-2 раскладывает текст **по схеме характеристик этого семейства** с цитатой из текста
   для каждого значения;
4. код проверяет цитаты, распознаёт единицы, переводит их в ОКЕИ, проверяет попадание в
   допустимые значения КТРУ со строгими/нестрогими границами;
5. код **сужает конечные позиции** семейства до одной; если осталось несколько — задаёт вопрос по
   самой информативной характеристике (кнопки, ответ без LLM); если ни одной — показывает
   значение-виновника и ближайшее допустимое;
6. собирает карточку СТЕ: унифицированные характеристики с источником значения, дополнительные
   характеристики, бренд/модель и список ошибок с обоснованием.

Онлайн — не больше двух вызовов LLM (§2); всё остальное — код и словари.

## Данные

Выгрузка КТРУ из `materials/КТРУ` (только `*_all_actual_*`, статус `ACTIVE`), охват — префиксы
ОКПД2 `14.` (одежда), `15.20` (обувь), `15.12` (сумки и рюкзаки), `31.` (мебель), `25.73` и `28.24`
(инструменты). База знаний собирается офлайн за ~30 с и лежит в репозитории:

| | |
| --- | --- |
| активных позиций в охвате | 1 797 |
| конкретных семейств (участвуют в выборе) | 288 |
| общих позиций без характеристик («…прочий») | 81 |
| конечных позиций (листьев) | 1 502 |
| файл | `backend/kb/ktru_kb.json.gz`, 200 КБ |

Семейство — корневая позиция и её дочерние (`parentPositionInfo`); глубина дерева везде 1.
Характеристики `kind=1` у листа фиксированы и **определяют лист**, `kind=2/3` — выбор из списка
(§1.5–1.6). Прежняя версия этого не использовала и сужала плоский список позиций.

## Что сделано поверх архитектуры

| Решение | Почему |
| --- | --- |
| LLM-1 получает **топ-30 из поиска**, а не все 288 семейств (`STE_FAMILY_SELECT_MODE`) | ~1,5 тыс. токенов вместо ~10 тыс.: быстрее и дешевле; критерий «скорость» — 5 баллов |
| **Быстрый путь**: однозначный поиск принимается без LLM-1 (`STE_FAST_PATH`) | экономит вызов и секунды там, где LLM-1 ничего бы не добавила |
| **Работа без LLM**: семейство по поиску, значения правилами по словарю семейства | бесплатный роутер бывает недоступен; сервис деградирует, а не падает |
| LLM-2 по нескольким семействам — **параллельно** | 2–3 кандидата не умножают задержку |
| LLM-2 возвращает только **упомянутые** характеристики, значения — строкой | меньше токенов; несуществующее значение доходит до проверки и становится ошибкой VALUE_NOT_ALLOWED, а не теряется в enum |
| Схема в промпте + проверка `jsonschema` + один «ремонт» (`STE_LLM_STRUCTURED=prompt`) | бесплатный провайдер игнорирует `response_format` (проверено); на платной модели — `json_schema` |
| Кэш ответов LLM на диске, ограничитель частоты, запасная модель, типизированные ошибки 429 | лимит 50 запросов в день; повтор демо — мгновенно |
| Вопрос задаётся и по **неуверенно** распознанной характеристике | слабое значение подтверждается одним нажатием |
| Дополнительные характеристики → **словарь типовых характеристик** портала (лист 2 выгрузок), единицы → ОКЕИ | §4.7: «унифицировано» и для того, чего нет в КТРУ |
| Единицы, которые реально пишут поставщики (по 300 тыс. строк выгрузок): `гр/м2`, `А.ч`, `Дж`, `мкм`, `МПа`… | без них «2 А.ч» не сравнить с «Ампер-час» |

## Что взято из прежней версии (`feature/opensearch`)

* принцип **«уверенно неверный код хуже честного „не нашли“»** — состояние `not_found` с
  подсказками вместо ближайшей строки;
* различение `greater`/`greaterOrEqual` в проверке и в объяснении;
* перевод соизмеримых единиц с показом обеих форм («500 г → 0,5 Килограмм»);
* исправление опечаток **к словарю КТРУ**, а не к общерусскому, с защитой правильного ввода;
* интерфейс в цветах Портала поставщиков, авторизация, Docker Compose.

OpenSearch убран: на 288 карточках семейств поиск в памяти быстрее и не требует отдельного
кластера; порт поиска оставлен, так что для полного КТРУ (60 тыс. позиций) движок
подключается одной реализацией.

## Ошибки и их объяснение (12 баллов)

`apps/ste/domain/signals.py`. Каждый сигнал — тип, характеристика, цитата пользователя,
**обоснование со ссылкой на КТРУ** и конкретный шаг исправления.

| Сигнал | Когда |
| --- | --- |
| `TYPO` | исправлена опечатка или раскладка |
| `OUT_OF_RANGE` | число не попадает ни в один интервал КТРУ («матрац 5 м» при 60–250 см) |
| `VALUE_NOT_ALLOWED` | значения нет в перечне КТРУ; предлагается ближайшее |
| `UNIT_MISMATCH` | единица другой размерности («толщина 25 кг») |
| `UNKNOWN_UNIT` | единица не распознана |
| `CONTRADICTION` | текст противоречит сам себе |
| `DUPLICATE_VALUE` | одна характеристика — разные значения |
| `CONFLICT` | значения вместе исключают все конечные позиции; назван виновник и ближайшее допустимое |
| `MISSING_REQUIRED` | после определения кода не хватает обязательных характеристик |
| `NOT_FOUND` | тип товара не найден в КТРУ — что уточнить |

## API

`/api/v1/ste/…`, сессионная авторизация, ответ — `Result` (§6.3):

| | |
| --- | --- |
| `GET preview/?q=` | похожие семейства по мере набора, без LLM |
| `POST analyze/ {text}` | полный разбор описания |
| `POST answer/ {session_id, char_key, value}` | ответ на вопрос кнопкой (`__unknown__` — «не знаю») |
| `POST answer-text/ {session_id, char_key, text}` | ответ текстом (мини-LLM-2) |
| `POST choose-family/`, `choose-leaf/`, `edit/` | выбор типа товара, позиции, ручная правка значения |

## Запуск

```bash
cp infra/.env.example infra/.env     # DJANGO_SECRET_KEY, POSTGRES_PASSWORD, STE_LLM_API_KEY
cd infra && docker compose up --build
```

Пересобрать базу знаний из новой выгрузки и векторы:

```bash
python manage.py build_ste_kb ../materials/КТРУ
python manage.py gen_family_meta          # синонимы семейств через LLM, ~12 запросов
python manage.py embed_ste_kb
```

Замер качества: `python -m apps.ste.eval --retrieval` (поиск, без LLM) и
`python -m apps.ste.eval --verbose` (весь пайплайн).
