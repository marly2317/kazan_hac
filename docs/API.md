# API

Базовый путь — `/api/v1/`. Интерактивная схема — `/api/v1/docs/` (Swagger UI по
сгенерированной OpenAPI), сырая схема — `/api/v1/schema/`.

Аутентификация — сессионная cookie. Небезопасные методы требуют заголовок `X-CSRFToken`;
получить cookie можно через `GET /api/v1/auth/csrf/`. Подробности и обоснование — в корневом
[README](../README.md#аутентификация).

Любая ошибка — доменная, DRF или неожиданная — приходит одним конвертом:

```json
{ "error": { "code": "invalid_credentials", "message": "…", "details": {} } }
```

`code` — стабильный машинный признак, по нему ветвится клиент; `message` — готовый текст.
Трассировка в ответ не попадает никогда.

## `GET /api/v1/autofill/analyze/`

Главный эндпоинт: разбирает свободное описание и сужает коды КТРУ.

`GET`, а не `POST`, намеренно — вызов является чтением, безопасен для повтора по мере ввода,
кэшируется и допускает ссылку.

| Параметр | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `description` | строка, ≤ 1000 | — | описание товара на естественном языке |
| `correct` | булево | `true` | `0` отключает исправление опечаток: пользователь увидел правку и отказался |
| `settled` | булево | `false` | `1` означает «описание дописано». Влияет **только** на сбор наблюдений о нехватке в справочнике — в ответе не отражается никак. Интерфейс ставит его при нажатии кнопки, Enter или подсказки, но не по паузе в наборе |

### Ответ

```jsonc
{
  "original":  "молоток слесарный масса головки 500 г",
  "corrected": "молоток слесарный масса головки 500 г",
  "text_changed": false,      // отличается ли разобранный текст больше, чем регистром
  "state": "ambiguous",       // resolved | ambiguous | not_found | empty
  "resolved_code": null,      // код только при state=resolved
  "confidence": 1.0,          // насколько описание называет лидирующую позицию, [0, 1]
  "total_candidates": 2,

  "characteristics": [{
    "name": "Масса головки молотка",
    "raw": "500 г",           // как написал пользователь
    "value": "0.5",           // после унификации
    "unit": "Килограмм",      // единица ОКЕИ после унификации
    "raw_unit": "г",
    "was_unified": true       // показывать переход «было → стало»
  }],

  "issues": [{
    "kind": "out_of_range",   // см. таблицу ниже
    "characteristic": "Высота шкафа",
    "raw": "9000 мм",         // фрагмент описания, к которому относится замечание
    "message": "Значение «9000 мм» не входит… КТРУ допускает: ≥ 400 … ≤ 2400 Миллиметр.",
    "suggestions": ["≥ 400 … ≤ 2400 Миллиметр"]
  }],

  "steps": [{                 // воронка сужения, в порядке применения
    "label": "Тип", "detail": "Слесарный",
    "before": 14, "after": 2, "eliminated": 12
  }],

  "candidates": [{
    "code": "25.73.30.141-00000011",
    "name": "Молоток",
    "okpd2_code": "25.73.30.141",
    "score": 2.7,             // итоговый ранг: сходство + подтверждения + покрытие
    "support": 2,             // сколько характеристик из описания позиция подтверждает
    "distinctions": ["Материал бойка: Алюминий, Медь, Сталь"]  // чем отличается от прочих
  }],

  "next_steps": [{
    "characteristic": "Материал бойка",
    "options": ["Сталь", "Алюминий", "Медь"],
    "splits_into": 3,
    "is_quantitative": false, // true → options это диапазоны, их нельзя дописать в описание
    "unit": ""
  }]
}
```

### `state`

| Значение | Смысл | Что показывать |
| --- | --- | --- |
| `resolved` | один код, уверенность достаточна | код как результат |
| `ambiguous` | подходит несколько | список с `distinctions` и `next_steps` |
| `not_found` | уверенность ниже порога | честное «не нашли» + близкие позиции |
| `empty` | кандидатов нет вовсе | предложить переформулировать |

`not_found` и `resolved` различаются не количеством: единственный выживший кандидат, на
который описание не похоже, — это `not_found`. Обоснование — в
[ALGORITHM.md](ALGORITHM.md#шаг-9-итог-и-что-уточнить).

### `issues[].kind`

| Вид | Серьёзность | Повод |
| --- | --- | --- |
| `typo` | предупреждение | слова нет в справочнике, подставлено ближайшее |
| `normalized` | **информация** | то же слово в форме справочника — не ошибка |
| `unknown_value` | ошибка | значения нет в перечне допустимых |
| `out_of_range` | ошибка | число вне всех допустимых диапазонов |
| `wrong_unit` | ошибка | единица несоизмерима с характеристикой |
| `unknown_unit` | предупреждение | слова нет в ОКЕИ и оно не называет характеристику |
| `missing_required` | предупреждение | обязательной характеристики нет в описании |
| `no_match` | ошибка | ни одна позиция не соответствует уверенно |

`normalized` отделён от `typo` намеренно: «колесиках» написано правильно, и объявлять там
опечатку — обвинять пользователя в ошибке, которой он не делал.

### Пример

```bash
curl -s -b cookies.txt -G \
  --data-urlencode 'description=молоток слесарный масса головки 500 г' \
  http://localhost:8080/api/v1/autofill/analyze/
```

## `GET /api/v1/autofill/suggest/`

Подсказки по мере набора — словарь КТРУ, а не произвольные русские слова.

| Параметр | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `text` | строка, ≤ 1000 | — | всё набранное на данный момент, **без** обрезки пробелов |
| `limit` | число 1…20 | 8 | сколько подсказок вернуть |

Пробел в конце `text` переключает режим: без него дополняется набираемое слово, с ним
предлагается следующее. Поэтому `trim_whitespace=False` — обрезав пробел, эндпоинт потерял бы
единственный признак, по которому эти режимы различаются.

```jsonc
{ "suggestions": [
  { "word": "зимняя", "kind": "position", "source": "Куртка зимняя из кожи" }
] }
```

`kind` — `position` | `characteristic` | `value`; определяет подпись и вес при ранжировании.
`source` — фраза справочника, откуда слово взято, для показа серым рядом с подсказкой.

Отдельный эндпоинт от разбора намеренно: подсказка нужна на каждый символ (дребезг 90 мс,
ответ 3–5 мс), разбор — на законченную мысль (350 мс, 39 мс). Связать их значило бы либо
гонять разбор по справочнику на каждое нажатие, либо показывать подсказки с задержкой в треть
секунды.

## Остальные эндпоинты

| Путь | Что делает |
| --- | --- |
| `GET /api/v1/auth/csrf/` | выдаёт cookie `csrftoken` |
| `POST /api/v1/auth/login/` | вход; `{email, password}` |
| `POST /api/v1/auth/register/` | регистрация |
| `POST /api/v1/auth/logout/` | выход |
| `GET /api/v1/auth/me/` | текущая учётная запись; 403, если сессии нет |
| `GET /api/v1/catalog/products/` | демонстрационный поиск по товарам с исправлением опечаток |
| `GET /healthz` | liveness для Compose, без обращения к БД |
