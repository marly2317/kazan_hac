## С чего начать

Если вы продолжаете разработку, порядок такой:

1. [ALGORITHM.md](ALGORITHM.md) — он объясняет **почему** код устроен именно так; почти
   каждое решение там продиктовано конкретным наблюдённым дефектом;
2. [DEVELOPMENT.md](DEVELOPMENT.md) — как поднять стенд и как проверить, что вы ничего не
   сломали;
3. [PLAN.md](PLAN.md) — что осталось.

Главное правило проекта в одну строку: **уверенно неверный код КТРУ хуже честного «не
нашли»**. Правка, повышающая точность за счёт ответов там, где ответа нет, — ухудшение.
