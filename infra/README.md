# infra

Развёртывание: Postgres, бэкенд, собранная SPA и один nginx перед ними.

```
docker-compose.yml   сервисы
nginx/nginx.conf     публичный вход
.env.example         шаблон окружения
```

```bash
cp .env.example .env     # заполнить DJANGO_SECRET_KEY и POSTGRES_PASSWORD
docker compose up --build
```

## Сервисы

| Сервис     | Образ / сборка   | Порт наружу | Роль                                    |
| ---------- | ---------------- | ----------- | --------------------------------------- |
| `postgres` | postgres:18      | —           | данные                                  |
| `backend`  | `../backend`     | —           | gunicorn, API и админка                 |
| `frontend` | `../frontend`    | —           | nginx со статикой сборки                |
| `nginx`    | nginx:1.29       | `8080`      | единственный публичный вход             |

Наружу смотрит только nginx. Это не косметика: бэкенд и SPA оказываются на **одном origin**,
поэтому сессионная cookie — своя, CORS не нужен, а `SameSite=Lax` достаточно.

Порядок старта задан через healthcheck: бэкенд ждёт готовности Postgres, nginx — готовности
бэкенда, иначе первые запросы приходят в ещё не поднявшийся контейнер.

Миграции применяет `backend/docker/entrypoint.sh` при старте. Это верно для одной реплики;
при нескольких перенесите шаг в отдельный одноразовый сервис, чтобы две реплики не мигрировали
одновременно.

## Postgres 18

Том примонтирован в `/var/lib/postgresql`, а не в `/var/lib/postgresql/data`: начиная с 18
образ держит кластер в подкаталоге с номером версии. При монтировании в `.../data` настоящий
PGDATA остаётся внутри контейнера и теряется при пересоздании.

## Перед реальным развёртыванием

* Терминировать TLS на nginx и выставить `SESSION_COOKIE_SECURE=1`, `CSRF_COOKIE_SECURE=1`.
  По обычному HTTP браузер `Secure`-cookie не сохранит — вход «пройдёт», а следующий запрос
  придёт анонимным.
* `DJANGO_ALLOWED_HOSTS` и `CSRF_TRUSTED_ORIGINS` — под реальное имя хоста.
  `CSRF_TRUSTED_ORIGINS` должен включать схему и порт ровно так, как адрес виден браузеру,
  иначе каждый POST падает на проверке CSRF.
* `SEED_DEMO_USER=0`.
* `DJANGO_SECRET_KEY` — из секрет-хранилища, а не из файла в репозитории.
