# Задача хакатона и соответствие решения

Конспект методических материалов Tender Hack (Казань, 2026) и состояние проекта относительно
них. Файл нужен, чтобы требования и ограничения не приходилось каждый раз перечитывать из PDF.

## Задача

**Автозаполнение ключевых характеристик в СТЕ.**

Пользователь вводит описание товара на естественном языке — в том числе с опечатками и
неполными данными. Сервис должен:

1. определить подходящие характеристики для конкретного товара;
2. сопоставить значения и единицы измерения, привести их к унифицированному виду;
3. **поэтапно сужать** множество категорий КТРУ по мере ввода характеристик — до одного
   итогового кода;
4. если по введённым характеристикам КТРУ однозначно не определяется — уведомить об этом и
   предложить конкретные шаги;
5. распознавать и исправлять ошибки в характеристиках (опечатки, явные несоответствия,
   несуществующие значения) **с обоснованием**;
6. показывать в интерфейсе, что было унифицировано и как идёт сужение кодов КТРУ.

Категории: **одежда, мебель, инструменты**.

## Ограничения (критично)

| Ограничение | Статус в проекте |
| --- | --- |
| Linux + веб-интерфейс | ✅ Docker Compose, nginx + SPA |
| ❌ Платные поисковые API (Yandex, Google Custom Search) | ✅ не используются |
| ❌ **Внешние API проприетарных LLM: OpenAI GPT, Google Gemini, Anthropic Claude «и другие подобные сервисы»** | ✅ удалено, см. ниже |
| ❌ low-code / no-code платформы | ✅ не используются |
| ✅ Только ОТКРЫТЫЕ модели, суммарно ≤ 40 ГБ VRAM, предпочтение лёгким и быстрым | ✅ основной путь — детерминированный, без модели |
| ✅ Роутеры LLM допускаются (timeweb, selectel), предпочтение отечественным | ⚙️ поддерживается через `LLM_BASE_URL` |

> **Было нарушение.** Первая версия исправления опечаток ходила в OpenRouter на
> `google/gemini-2.5-flash-lite` — это прямо запрещённый пункт. Стадия переписана: клиент
> (`apps/spellcheck/infrastructure/llm.py`) не называет ни вендора, ни модель, говорит на
> OpenAI-совместимом протоколе и **по умолчанию выключен**. Подключать только открытую модель:
> локальный vLLM/Ollama либо отечественный роутер.

## Критерии оценки (100 баллов)

| Критерий | Баллы |
| --- | --- |
| Понимание проблематики | 7 |
| Функциональность и качество решения | **40** |
| Распознавание ошибок | **12** |
| Пользовательский интерфейс | 10 |
| Техническая реализация и масштабируемость | 16 |
| Презентация, команда, защита | 15 |

Внутри «Распознавания ошибок» (12):

* выявление опечаток, ошибок раскладки, пропусков и перестановок — **1**;
* **выявление явных несоответствий и несуществующих значений — 8**;
* качество автоматического исправления — **3**.

> Значит, чистый спелл-чекер стоит 1 балл из 12. Основной вес — проверка значения на
> **соответствие справочнику КТРУ** (допустимые значения, диапазоны, единицы) с объяснением,
> почему значение неверно. Это определяет приоритеты доработки.

Отдельно требуется **схема реализации в нотации BPMN** для защиты.

## Исходные данные

```
КТРУ/КТРУ/*.zip                 183 архива, nsiKTRUNew_all_actual_*.xml
                                (файлы *_not-actual_* организаторы просят игнорировать)
Примеры выгрузок/*.xlsx         Инструменты, Мебель, Одежда — реальные СТЕ
```

Структура КТРУ, по которой написан парсер `apps/ktru/infrastructure/xml_parser.py`:

```
position/data
├── code              25.73.30.141-00000001      ← целевой код
├── name              Молоток
├── status            ACTIVE | TERMINATED        ← берём только ACTIVE
├── OKPD2/code,name   25.73.30.141
└── characteristics/characteristic
    ├── name          Длина рукоятки
    ├── type          1 качественная | 2 количественная
    ├── actual        false → характеристика снята
    ├── isRequired    обязательная ли
    └── values/value
        ├── qualityDescription          «Пластик»           (качественная)
        ├── valueSet/concreteValue      200                 (точное значение)
        ├── rangeSet/valueRange         min/max + minMathNotation/maxMathNotation
        └── OKEI/code,name              003 / Миллиметр     (единица измерения)
```

Важно: `greater`/`less` **исключают** границу, `greaterOrEqual`/`lessOrEqual` — включают.
Перепутать означает принять значение, которое КТРУ отвергает, — ровно та ошибка, которую
оценивают.

В выгрузках СТЕ характеристики лежат одной строкой: `Вес 2.03000 кг | Высота упаковки 100 мм |
…`. В них встречаются реальные ошибки — например, `Кострукция сварная` в «Мебель.xlsx».

## Словарь исправлений — почему КТРУ, а не обычный русский

Исправлять нужно **в сторону слов, которые есть в справочнике**: цель потока — довести
пользователя до кода КТРУ, и исправление на слово, которого в КТРУ нет, уводит от неё.
Источник словаря — `apps/ktru/infrastructure/vocabulary.py`: наименования характеристик (вес 6),
допустимые текстовые значения (5), единицы ОКЕИ (4), наименования позиций (2).

Биграммы нужны там, где частота бессильна: «кожы» одинаково близко к «кожа» и «кожи», и только
соседнее слово решает — в справочнике есть «из кожи» и нет «из кожа».
